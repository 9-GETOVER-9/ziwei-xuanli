# 紫微玄历：今日圣诞首页设计

## 已确认的目标

用户打开网页时，先看到今天的道历日期与神仙圣诞。若同日有多位神仙，首页突出一位，其余列在下方。首版只展示已经逐字核对且记录出处的宝诰正文。神像图片以后补入。

## 方案选择

采用“今日首页 + 现有月历”两层结构。首页回答今天是什么日子、主神是谁、可读的宝诰是什么；月历继续承担浏览其他日期、筛选与搜索的任务。这样能复用现有日期和事件数据，并让用户一打开网页就得到核心内容。

备选方案：仅在现有月历上加大今日侧栏，改动较小，但手机屏幕目前隐藏侧栏，无法满足打开即见；另一个方案是完全重做页面，会增加工作量，也会丢掉现有月历价值。

## 页面行为

1. 默认进入“今日”页，以用户设备当前日期计算公历、农历与道历日期，明确显示日期。
2. 今日有圣诞时，主卡片显示一位神仙的名称、圣诞名称、简介及宝诰区域。同日其他圣诞按原事件顺序列在下面，点击可切换主卡片。
3. 主卡片默认选择：优先有已核对宝诰且有关联神仙资料的圣诞；其余按历例原顺序。页面应说明主卡片只是展示排序，不代表神格高低。
4. 今日无圣诞时，主卡片显示“今日暂无收录的神仙圣诞”，下方仍可列出斋期等其他事件，并提供月历入口。
5. 宝诰正文只有在记录了正文、书名或正式科本、具体出处、核对状态后才能展示。现有 HTML 中仅有书名或标为“节选”的内容暂不视为已核对。
6. 图片区域先用不冒充神像的简洁装饰或留白；将来由用户确定素材后再接入，并记录图片来源。
7. “月历”入口保留目前的筛选、搜索、神系图与神仙资料弹窗。日期计算和原有事件数据在原型阶段继续复用。

## 数据与边界

将圣诞事件与神仙资料通过稳定 ID 关联。宝诰作为独立记录，至少包含神仙 ID、正文、版本或出处、核对状态。没有已核对宝诰的神仙仍可展示圣诞与简介，但宝诰区域明确显示“原文待核对”，不以占位文案冒充正文。

首版不制作神像、不引入账号、后台、提醒通知或数据库。节日和宝诰校勘是内容工作，不由页面代码推断真实性。现有浏览器农历换算与节气规则要另行核验，尤其是边界日期和不同浏览器一致性。

## 验收

- 打开网页直接出现今天的信息；手机和电脑都可看到主卡片及其他圣诞。
- 同日多位圣诞可切换主卡片；没有圣诞时仍有清楚的空状态。
- 未核对宝诰不作为正文显示；已核对记录显示可追溯出处。
- 可进入现有月历并返回今日；原有搜索、筛选和神系图不因首页改动失效。

## 当前阶段

用户已同意按此方向开发。已制作可浏览的首页原型，待用户体验后再决定下一轮页面和内容录入范围。
